# Slide Type Variations

## Overview

Five slide types exist, each a data shape dispatched by `type` in `src/components/Slide.jsx` to a matching component. Don't invent a sixth type for content that already fits one of these — the builders in `adding-lessons` cover the common cases automatically.

## Quick reference

| type | shape | used for | built by |
|---|---|---|---|
| `cover` | `{ kicker, title, sub, node: { top, bottom } }` | one per trilha, the intro slide before any aula | written directly in the trilha file (`export const cover = ...`), not a builder |
| `divider` | `{ num, tag, title }` | first slide of every aula | auto-generated by `nonTechLesson`/`techLesson` |
| `agenda` | `{ tag, items, active }` | lesson menu; `active` (0-based index, or `-1`) highlights the current item | auto-generated, interleaved between points/blocks |
| `point` | `{ tag, title, text }` | one talking idea, no steps | `pontos` in `nonTechLesson`, or `{ type: 'point', ... }` inside a `techLesson` block |
| `tecnica` | `{ tag, title, steps, shotBox, note }` | one block of UI steps, optional screenshot placeholder | `blocos` in `techLesson` |

Never construct these objects by hand for a new aula — use the builders (`adding-lessons` skill). Hand-written shapes are only for one-offs like the trilha's `cover`.

## When an existing type doesn't fit

Before adding a new type, check whether the content is really a variation already supported:
- A `tecnica` block with no screenshot → `shotBox: false`, not a new type.
- A talking point inside a technical lesson → `{ type: 'point', ... }` block, not a new type.
- A caveat under steps → `note` field, not a new type.

If the content genuinely needs new layout (e.g. a comparison table, a two-column point), add a new type:

1. Add the data shape convention (document it here, in this table).
2. Create `src/components/<Type>.jsx` — a plain component reading its slide's fields as props, following the existing components (`Point.jsx`, `Tecnica.jsx`) as the pattern: no internal state, no navigation logic, just render.
3. Register it in the `TYPES` map in `src/components/Slide.jsx`.
4. Style it in `src/index.css` under a `.<type> ...` block, reusing existing tokens (`--accent`, `--muted`, `--line`, etc.) and the `.col` / `.grid` layout conventions — slides render inside a fixed 1920×1080 `#stage` (see `DeckView.jsx`'s `fitStage`), so don't use viewport units or `100%`-of-window sizing inside a slide.
5. Extend a lesson builder (or write the object directly, if it's a one-off like `cover`) to produce it.

## Verify

`npm run build` catches shape mismatches (missing prop a component expects) at build time for anything the builders touch; a hand-written object only fails at render, so preview it (`npm run dev`) after adding a new type.
